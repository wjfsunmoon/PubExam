## 一、项目概述

### 1.1 这是什么

一个面向公务员考试备考场景的**全栈智能题库系统**。核心能力：粘贴一道考公题目 → AI 自动生成六段式结构化解析（破题眼 / 正确项分析 / 干扰项排雷 / 方法总结 / 备考提醒）→ 沉淀到题库 → 支持检索、筛选、导出。

### 2.2 请求生命周期（以"获取题库列表"为例）

```
1. 用户在浏览器输入 → 浏览器发 GET /api/questions
2. Express 收到请求
3. cors() 中间件 → 添加 CORS 头
4. express.json() 中间件 → 解析请求体（GET无body，跳过）
5. router.use(authenticate) → 从 Authorization 头提取 Bearer token
6. jwt.verify(token, secret) → 验证签名，提取 userId
7. req.userId = payload.userId → 后续路由可用
8. 路由处理器执行：
   - 构建 where 条件 { userId, module?, difficulty? }
   - prisma.question.findMany() → 查询数据库
   - prisma.question.count() → 统计总数
   - serialize() → 序列化为API响应格式
9. res.json({ items, total, ... }) → 返回JSON
10. Axios 响应拦截器 → 检查是否401 → 否，放行
11. React setState → 页面重新渲染 → 题目列表显示
```

### 2.3 单端口部署架构（关键设计决策）

**问题**：开发时 Vite dev server (5173) 和 Express (3001) 两个端口，用户访问哪个？

**方案**：生产模式用 Express 同时服务 API + 静态前端

```javascript
// server/src/index.js 中的关键代码

// 1. API 路由优先匹配
app.use('/api/auth', authRoutes);
app.use('/api/questions', questionRoutes);
app.use('/api/analysis', analysisRoutes);

// 2. API 404 —— 仅 /api/* 返回 JSON 错误
app.use('/api', (req, res) => {
  res.status(404).json({ error: `路由不存在: ${req.method} ${req.path}` });
});

// 3. 静态文件 —— 服务构建后的 React 产物
app.use(express.static(clientDist));  // clientDist = ../../client/dist

// 4. SPA fallback —— 所有非API的GET请求返回index.html
app.get('*', (req, res) => {
  res.sendFile(join(clientDist, 'index.html'));
});
```

**为什么要 SPA fallback？** React Router 使用 BrowserRouter（路径路由），当用户直接访问 `/login` 或 `/bank` 时，Express 找不到对应的静态文件，需要返回 `index.html` 让 React Router 在客户端处理路由。

## 三、核心模块详解

### 3.1 数据库设计（Prisma Schema）

```prisma
// server/prisma/schema.prisma

model User {
  id        Int        @id @default(autoincrement())
  username  String     @unique        // 唯一约束，防止重名
  password  String                     // 存的是 bcrypt 哈希值，不是明文！
  createdAt DateTime   @default(now())
  questions Question[]                 // 一对多关系
}

model Question {
  id            Int      @id @default(autoincrement())
  userId        Int
  user          User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  // onDelete: Cascade → 用户被删时，其题目自动级联删除

  // 元数据
  module       String    // 行测/申论/公基/面试
  submodule    String    // 判断推理/言语理解/...
  questionType String    // 削弱型/加强型/...
  difficulty   Int       // 1-5
  tags         String    // JSON 字符串: ["另有他因","因果论证"]
  frequency    String    // 高频/中频/低频
  year         String?

  // 题目内容
  stem          String    // 题干全文
  options       String    // JSON: [{label:"A",content:"..."}]
  correctAnswer String    // "A"

  // 结构化解析（六个维度）
  breakthrough    String?  // 破题眼
  correctAnalysis String?  // 正确项分析
  trapAnalysis    String?  // 干扰项排雷 JSON
  methodSummary   String?  // 方法总结
  examTips        String?  // 备考提醒

  // AI 元数据
  analysisSource String?  // "ai" / "manual" / "template"
  aiModel        String?  // 记录用了哪个模型

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([userId])                 // 查询用户题目时走索引
  @@index([module, submodule])      // 按模块筛选时走联合索引
}
```

**设计要点：**
- **JSON 存储为 String**：SQLite 不原生支持 JSON 类型，tags/options/trapAnalysis 以 JSON 字符串存储，应用层 `JSON.parse/stringify` 转换。如果用 PostgreSQL 可以直接用 Prisma 的 `Json` 类型。
- **级联删除**：用户注销时自动删除其所有题目，避免孤儿数据。
- **联合索引**：`@@index([module, submodule])` 优化按模块筛选的查询性能。
- **软关联 vs 硬关联**：tags 不建独立表（避免多表 JOIN 的复杂度），直接用 JSON 字符串存储，适合标签数量少、不需要按标签反查的场景。

### 3.2 JWT 认证流程

```
┌─────────────────────────────────────────────────────────┐
│                    注册流程                                │
│  POST /api/auth/register { username, password }          │
│                                                          │
│  1. 校验用户名/密码格式                                     │
│  2. 检查用户名是否已存在 (prisma.user.findUnique)          │
│  3. bcrypt.hash(password, 10) → 生成哈希（加盐10轮）       │
│  4. prisma.user.create() → 写入数据库                      │
│  5. jwt.sign({ userId }, secret, { expiresIn: '7d' })    │
│  6. 返回 { token, user: { id, username } }                │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│                    登录流程                                │
│  POST /api/auth/login { username, password }              │
│                                                          │
│  1. prisma.user.findUnique({ username }) → 查到用户       │
│  2. bcrypt.compare(password, user.password) → 验证哈希    │
│  3. jwt.sign() → 生成token                                │
│  4. 返回 { token, user }                                  │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│                    请求鉴权（每个受保护路由）               │
│  GET /api/questions  Header: Authorization: Bearer xxx   │
│                                                          │
│  1. 从 Authorization 头提取 token                         │
│  2. jwt.verify(token, secret) → 验证签名+检查过期          │
│  3. req.userId = payload.userId → 挂载到请求对象           │
│  4. next() → 进入路由处理器                                │
│  5. 路由内用 req.userId 过滤当前用户的题目                  │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│                    前端处理                                │
│  Axios 请求拦截器：                                        │
│    从 localStorage 取 token → 注入 Authorization 头        │
│  Axios 响应拦截器：                                        │
│    收到 401 → 清除 token → 跳转 /login                     │
└─────────────────────────────────────────────────────────┘
```

**为什么选 JWT 不选 Session？**
- JWT 无状态：服务器不需要存储 session，水平扩展时不需要共享 session 存储
- 前后端分离友好：token 可以放在 localStorage / cookie，跨域方便
- 移动端友好：如果后续做 App 端，JWT 天然适配

**JWT 的结构（三段式）：**
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9   ← Header (算法: HS256)
.eyJ1c2VySWQiOjEsImlhdCI6...          ← Payload (userId, iat, exp)
.J7FMH7CaMQ_qnXiYiohks...             ← Signature (HMAC签名)
```

这是项目最核心的"智能"部分，架构如下：

```
┌─────────────────────────────────────────────────┐
│              用户点击 "生成解析"                    │
│  POST /api/analysis/generate                     │
│  body: { metadata, question }                    │
└───────────────────┬─────────────────────────────┘
                    │
         ┌──────────▼──────────┐
         │  ai.js analyzeQuestion │
         │  检查 OPENAI_API_KEY   │
         └──────────┬──────────┘
                    │
          ┌─────────┴─────────┐
          │                   │
    有API Key            无API Key
          │                   │

  │  callLLM()    │   │  template() │

  │ 1.构建prompt   │   │ 生成框架     │
  │ 2.调用API     │   │ 标注"待AI"   │
  │ 3.解析JSON    │   └─────────────┘
  │ 4.返回结果     │
  └───────────────┘

**Prompt 设计（两层）：**

```javascript
// server/src/utils/prompts.js

// 第一层：System Prompt —— 定义角色、约束、输出格式
export const SYSTEM_PROMPT = `你是一位拥有10年以上国考/省考命题研究与
教学经验的资深公考教研专家。请对以下考公题目进行深度解析。

## 解析原则（绝对红线）
1. 禁止编造：不确定的知识点必须标注"待核实"
2. 政治中立：严格遵循官方表述
3. 拒绝模糊：不使用"可能""大概"等词汇
4. 涉法律/政策题，以最新有效版本为准

## 输出格式
请严格输出以下JSON格式（不要输出其他内容）：
{
  "breakthrough": "...",
  "correctAnalysis": "...",
  "trapAnalysis": [{ "option": "B", "errorType": "...", "explanation": "..." }],
  "methodSummary": "...",
  "examTips": "..."
}`;

// 第二层：User Prompt —— 注入题目上下文
export function buildUserPrompt(questionData) {
  return `## 题目元数据
- 模块: ${meta.module}
- 题型: ${meta.questionType}
...
## 题干
${que.stem}
## 选项
${optionsText}
## 正确答案
${que.correctAnswer}
请按照系统提示中的格式要求输出结构化解析。`;
}
```

**为什么这样设计 Prompt？**
- **System + User 分离**：System 定义不变的角色和约束，User 注入可变的题目数据，这是 OpenAI Chat API 的标准模式
- **JSON 输出约束**：明确要求输出 JSON 格式，便于程序解析。temperature 设为 0.3 降低随机性
- **红线约束**：在 prompt 中嵌入业务规则（禁止编造、政治中立等），确保输出符合教研标准
- **降级策略**：无 API Key 时自动降级为模板模式，保证流程可走通，不会因为缺少配置就报错

**JSON 解析的容错处理：**
```javascript
// LLM 可能返回 ```json ... ``` 包裹的内容，需要清洗
const jsonStr = content
  .replace(/```json\s*/g, '')
  .replace(/```\s*/g, '')
  .trim();

try {
  analysis = JSON.parse(jsonStr);  // 正常解析
} catch {
  // JSON 解析失败时，将原始文本作为 correctAnalysis 返回
  analysis = {
    breakthrough: '[解析格式异常]',
    correctAnalysis: content,  // 保底：不丢内容
    ...
  };
}
```

### 3.4 Express 中间件链

Express 的核心设计理念就是**中间件管道**——请求像水流一样依次穿过每个中间件：

```javascript
// server/src/index.js

app.use(cors());                          // ① 跨域：添加 Access-Control-Allow-* 头
app.use(express.json({ limit: '10mb' })); // ② 解析 JSON 请求体（限制10MB防攻击）

app.get('/api/health', ...);              // ③ 健康检查（不需认证）

app.use('/api/auth', authRoutes);         // ④ 认证路由（注册/登录，不需JWT）
app.use('/api/analysis', analysisRoutes); // ⑤ 解析路由（需JWT）
app.use('/api/questions', questionRoutes);// ⑥ 题目路由（需JWT）

app.use('/api', (req, res) => {           // ⑦ API 404 处理
  res.status(404).json({ error: '...' });
});

app.use(express.static(clientDist));       // ⑧ 静态文件服务
app.get('*', (req, res) => {              // ⑨ SPA fallback
  res.sendFile(join(clientDist, 'index.html'));
});

app.use((err, req, res, _next) => {       // ⑩ 全局错误处理（4参数=错误处理中间件）
  console.error('Unhandled error:', err);
  res.status(500).json({ error: err.message });
});
```

**关键知识点：**
- 中间件执行顺序 = 注册顺序。先 cors 再 json 再路由
- `app.use(path, router)` —— 路径前缀匹配，挂载子路由
- 错误处理中间件必须 4 个参数 `(err, req, res, next)`，Express 通过参数数量识别
- `next()` 调用才进入下一个中间件，不调用则链终止

### 3.5 React 组件设计与状态管理

```
App.jsx
├── /login → Login.jsx（无鉴权）
└── ProtectedRoute → Layout.jsx（需鉴权）
    ├── Navbar.jsx
    ├── Outlet（嵌套路由出口）
    │   ├── / → Dashboard.jsx
    │   ├── /entry → QuestionEntry.jsx
    │   ├── /bank → QuestionBank.jsx
    │   └── /question/:id → QuestionDetail.jsx
    └── Footer

全局状态：AuthContext
├── user（当前用户信息）
├── login(token, userData)
├── logout()
├── loading（初始加载状态）
```

**为什么用 Context API 不用 Redux？**
- 全局状态只有 `user` 一个，复杂度低
- Redux 引入 action/reducer/store 三层概念，对小项目是过度设计
- Context + useState 就能解决跨组件状态共享

**路由守卫实现：**
```javascript
// ProtectedRoute.jsx
export default function ProtectedRoute({ children }) {
  const { user, loading } = useAuth();

  if (loading) return <div>加载中...</div>;     // 等待 localStorage 读取
  if (!user) return <Navigate to="/login" />;   // 未登录→重定向
  return children;                               // 已登录→渲染子组件
}
```

### 3.6 Axios 拦截器设计

```javascript
// client/src/api/index.js

// 请求拦截器：每个请求自动带上 JWT
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// 响应拦截器：401 自动登出跳转
api.interceptors.response.use(
  (response) => response,           // 2xx 直接放行
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem('token');
      localStorage.removeItem('user');
      window.location.href = '/login';  // token过期→强制重新登录
    }
    return Promise.reject(error);       // 非401错误继续抛出
  }
);
```

**好处**：不用在每个 API 调用处手动加 token，统一处理认证逻辑。

### 3.7 数据序列化（DB → API 响应）

数据库存储的是扁平结构（JSON 存为字符串），API 需要返回嵌套结构：

```javascript
// server/src/routes/questions.js

function serialize(q) {
  return {
    id: q.id,
    metadata: {           // ← 从扁平字段聚合为对象
      module: q.module,
      submodule: q.submodule,
      questionType: q.questionType,
      difficulty: q.difficulty,
      tags: JSON.parse(q.tags || '[]'),   // ← 字符串→数组
      frequency: q.frequency,
      year: q.year,
    },
    question: {
      stem: q.stem,
      options: JSON.parse(q.options || '[]'),  // ← 字符串→数组
      correctAnswer: q.correctAnswer,
    },
    analysis: {
      breakthrough: q.breakthrough,
      correctAnalysis: q.correctAnalysis,
      trapAnalysis: q.trapAnalysis ? JSON.parse(q.trapAnalysis) : null,
      methodSummary: q.methodSummary,
      examTips: q.examTips,
    },
    // ...
  };
}
```

**为什么这样做？** 分离存储格式和 API 契约。数据库怎么存是内部实现，API 返回什么是对外契约，两者解耦。

## 四、数据库迁移

### 4.1 什么是迁移

迁移 = 数据库 schema 的版本控制。每次修改 schema，Prisma 生成一个迁移文件，记录了 SQL DDL 语句。

```
prisma/migrations/
├── migration_lock.toml              # 锁定数据库类型
└── 20260919063610_init/
    └── migration.sql                # 建表SQL
```

### 4.2 迁移命令

```bash
# 1. 生成迁移并应用
npx prisma migrate dev --name <迁移名>

# 2. 仅生成Prisma Client（schema变了但不想生成迁移）
npx prisma generate

# 3. 重置数据库（危险！清空数据）
npx prisma migrate reset

# 4. 种子数据
npx prisma db seed
```

### 4.3 clone 后的初始化流程

```bash
cd server
npm install                    # 安装依赖
npx prisma generate            # 生成 Prisma Client
npx prisma migrate dev         # 应用迁移，创建表
npx prisma db seed             # 填充种子数据
```

## 五、关键设计决策汇总

| 决策 | 选择 | 替代方案 | 理由 |
|------|------|---------|------|
| 数据库 | SQLite | MySQL/PostgreSQL | 零配置，文件级，适合个人项目和演示 |
| ORM | Prisma | Sequelize/TypeORM/原生SQL | 类型安全，Schema直观，迁移自动化 |
| 认证 | JWT | Session+Cookie | 无状态，前后端分离友好 |
| 密码加密 | bcrypt | MD5/SHA256 | bcrypt加盐+慢哈希，防彩虹表攻击 |
| 前端框架 | React | Vue/Angular | 生态最大，就业市场需求最高 |
| CSS方案 | Tailwind | Sass/Less/CSS Modules | 原子化，开发快，无需命名 |
| 状态管理 | Context API | Redux/Zustand | 状态简单，不过度设计 |
| HTTP客户端 | Axios | fetch | 拦截器机制，自动JSON转换 |
| JSON存储 | String字段 | 关联表 | 标签等小数据用JSON足够，避免JOIN复杂度 |
| AI降级 | 模板模式 | 直接报错 | 保证无API Key时也能演示完整流程 |
| 部署模式 | 单端口 | 前后端分离部署 | Express同时服务API+静态文件，简化部署 |
